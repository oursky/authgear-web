> **tl;dr**：CIAM（客戶身分與存取管理）是讓客戶在你的 App 裡自己註冊、登入、管理帳號的系統，同時讓你以安全、尊重使用者同意的方式，大規模掌控客戶的身分資料。

只要你做的產品有公司外部的人需要登入，你其實就已經有一套 CIAM 系統了。它可能是一張使用者資料表加上一個 bcrypt 套件，可能是一個託管服務，也可能是你自己架設的開源伺服器。本文說明 CIAM 是什麼、它和 IT 部門用的 IAM 有什麼不同、哪些功能真正重要，以及該怎麼決定它要部署在哪裡。

## 什麼是 CIAM？

客戶身分與存取管理涵蓋了從「陌生人來到你的註冊頁」到「已知客戶看到正確資料」之間的所有環節：

- **註冊**：客戶自己建立帳號。
- **身分驗證**：用密碼、通行密鑰、一次性驗證碼或社群帳號，確認真的是本人。
- **授權**：決定登入後的客戶能看什麼、能做什麼。
- **帳號管理**：修改個人資料、重設密碼、連結其他登入方式、刪除帳號。
- **同意與隱私**：記錄客戶同意了哪些事，並讓他們可以改變心意。

**打個比方。** 想像一間飯店。員工從側門進出，配戴入職第一天人資發的識別證，這是員工用的 IAM。房客則在任何時間走到櫃台，常常沒有訂房，卻希望一分鐘內就能完成入住；有人每週都來，有人只來一次，也有少數人想混進來。那個櫃台就是 CIAM。同一棟建築，工作內容卻完全不同。

## CIAM 和 IAM 有什麼不同？

員工用的 IAM（有時直接簡稱 IAM）管理員工與約聘人員，CIAM 管理客戶。兩者都處理登入、工作階段和權限，但另一端的使用者行為不同，優先順序也跟著改變。

| | 員工用的 IAM | CIAM |
|---|---|---|
| **使用者是誰** | 員工、約聘人員、合作夥伴 | 客戶與一般大眾 |
| **規模** | 數百到數萬人，相對穩定 | 數千到數百萬人，上市或活動時會暴增 |
| **帳號怎麼建立** | 由 IT 或人資建立 | 客戶自己註冊 |
| **社群登入** | 很少用到 | 基本配備：Google、Apple、Facebook 等 |
| **品牌設計** | 公司制式的登入頁就夠了 | 必須和你的產品風格一致 |
| **同意與隱私** | 由勞動契約涵蓋 | 需要明確同意、隱私設定與自助刪除 |
| **MFA 做法** | 可以強制且嚴格 | 必須低摩擦，否則客戶會流失 |
| **誰來管理帳號** | IT 管理員 | 客戶自己，加上你的客服團隊 |

最大的差別在於：客戶登入流程每多一個步驟，你就會少掉一些註冊。員工因為非用不可，會忍受麻煩的 MFA 提示；客戶則可以直接離開。

### Keycloak 的定位

[Keycloak](https://www.keycloak.org/) 是介於兩者之間的好例子。它的官網稱自己為「Open Source Identity and Access Management」，採用 Apache 2.0 授權，是 Cloud Native Computing Foundation 的孵化專案，強項在員工端的需求：LDAP 與 Active Directory 整合、SAML 與 OpenID Connect 身分代理，以及集中式的管理主控台。

很多團隊也用 Keycloak 做客戶登入，它也具備基本元件：自助註冊、可在管理主控台設定的社群登入，以及讓使用者更新個人資料、設定兩步驟驗證、管理工作階段的帳號主控台。要讓它像一個面向客戶的產品，團隊通常會：

- **開發自訂主題。** 登入頁是 FreeMarker 樣板，要符合你的品牌，就得自己撰寫並維護主題。
- **撰寫擴充套件。** 客製化行為要寫成 Service Provider Interface（SPI）provider，也就是打包成 JAR 部署到伺服器上的 Java 程式碼。
- **升級後重新測試。** 每次 Keycloak 推出新版本，自訂主題和 provider 都得重新檢查。

如果你有 Java 人力、又想要完全的掌控權，這是合理的取捨。如果你不想維護這一層，可以看看從一開始就為客戶登入而設計的工具。我們的 [Authentik vs Keycloak 比較](/zh-hant/post/best-self-hosted-sso-platforms-compared-authgear-vs-keycloak-vs-authentik) 有更詳細的說明。

## CIAM 必備功能檢查清單

不論你打算自己開發、採購，還是自行部署，都可以用這份清單來評估任何 CIAM 方案。

- **自助註冊。** 客戶不用等任何人就能註冊，並透過電子郵件或手機號碼驗證。
- **社群登入。** 「使用 Google 繼續」或「使用 Apple 登入」能讓註冊流程少掉一組密碼。
- **通行密鑰與無密碼登入。** 通行密鑰、魔術連結和一次性驗證碼能減少重設密碼的需求，也能抵擋網路釣魚。
- **客戶願意接受的 MFA。** 只在風險較高時才加強驗證，例如新裝置或付款，而不是每次登入都要輸入驗證碼。
- **有品牌感的登入頁。** 使用你的字型、色彩和用語，放在你自己的網域上，讓客戶信任他們正在輸入資料的頁面。
- **帳號連結與去重複。** 同一個人先用電子郵件註冊、之後又用 Google 登入，應該只會有一個帳號，而不是兩個。
- **同意與隱私控制。** 記錄每位客戶同意了什麼，讓他們可以修改，也可以匯出或刪除自己的資料。
- **機器人防護。** 用 CAPTCHA、速率限制和暴力破解防護，擋下假註冊、撞庫攻擊和 SMS pumping 詐騙。
- **使用者管理。** 讓客服團隊能找到客戶、重設存取權、停用帳號，並查看近期活動的主控台。
- **跨應用程式的 SSO。** 讓網站、行動 App 和子品牌共用同一個登入。
- **API 與 SDK。** 標準的 OAuth 2.0 與 OpenID Connect，加上網頁、iOS、Android，以及 React Native、Flutter 等跨平台框架的 SDK。
- **規模與穩定性。** 登入位在關鍵路徑上，登入掛了，你的產品也就掛了。

稽核紀錄也應該列在清單上。如果你需要證明誰在什麼時候做了什麼，請參考我們的 [CIAM 稽核與合規指南](/zh-hant/post/auditing-and-compliance-in-ciam-logs-events-controls)。

## CIAM 該部署在哪裡

CIAM 系統存放的是你最敏感的一部分資料：姓名、電子郵件、電話號碼、密碼雜湊值和登入紀錄。所以「它部署在哪裡、由誰維運」和功能清單一樣重要。常見的模式有三種。

| | 託管 SaaS | 自行部署的開源方案 | 替你維運的私有雲 |
|---|---|---|---|
| **由誰維運** | 廠商，在共用的基礎設施上 | 你的團隊 | 廠商，在專屬部署上 |
| **資料放在哪裡** | 廠商提供的區域 | 你部署在哪裡就在哪裡 | 你指定的區域 |
| **你的團隊要花多少力氣** | 最少 | 最多：升級、擴充、備份、輪值 | 少 |
| **掌控程度** | 限於廠商提供的設定 | 完全掌控 | 高，通常可約定稽核權 |

對金融、醫療和公部門相關的團隊來說，這個選擇往往不只是方便與否。資料落地回答的是「伺服器在哪個國家」；資料主權還要問「系統由誰維運、維運者受哪個國家的法律管轄」。

如果主管機關、大客戶或公部門標案問你使用者資料放在哪裡，地端部署或在你指定區域的私有雲，能讓你給出清楚的答案。

## 如何挑選 CIAM 方案

給開發者、技術長和 IT 主管的簡短檢查清單：

1. **從你的使用者出發。** 是一般消費者、企業客戶，還是兩者都有？B2B 產品除了自助註冊，可能還需要企業 SSO（SAML、Microsoft Entra ID）。
2. **決定資料必須放在哪裡。** 把國家和原因寫下來：法規、合約、採購規範。這能很快縮小部署模式的範圍。
3. **親自試一次登入體驗。** 在手機上註冊、用通行密鑰登入、重設密碼、刪除帳號，數一數總共要幾個步驟。
4. **確認品牌客製化能做到多深。** 只能換色彩和標誌，還是能完全掌控 HTML 和 CSS？
5. **看清楚退場路線。** 能不能連同密碼雜湊值一起匯出使用者？程式碼是否開源，讓你在廠商改變方向時仍能繼續運作？
6. **算清楚維運成本。** 自行部署時，除了伺服器費用，也要算進升級、監控和安全修補的人力時間。
7. **以成長目標估價。** 很多 CIAM 方案按每月活躍使用者計價，請用目前使用者人數的十倍來估算成本。

### 開源 CIAM 選項

如果開源對你很重要，主要可自行部署的選擇有 Keycloak、Authentik、Ory、ZITADEL 和 Authgear。它們在程式語言、授權、客戶體驗的現成程度，以及是否有託管選項上各有不同。

[Authgear](/zh-hant/solutions/data-sovereignty) 是開源的 CIAM，採用 Apache 2.0 授權，為面向客戶的網頁與行動 App 打造。你可以自行部署並使用所有功能，也可以由我們在你指定的區域替你維運私有雲。登入頁在每個方案（包括自行部署）都能完整自訂 HTML 和 CSS，也能連同 bcrypt 密碼雜湊值匯入既有使用者。如果你正打算從 Keycloak 搬家，請看 [Keycloak 替代方案](/compare/keycloak-alternative) 頁面（英文）。

## 常見問題

### 什麼是 CIAM？

CIAM 是 Customer Identity and Access Management 的縮寫，中文是客戶身分與存取管理。它讓你的 App 或網站的客戶能自己註冊、登入、找回帳號並管理自己的資料，也讓你的團隊能安全、大規模地管理這些帳號。

### CIAM 和 IAM 有什麼不同？

員工用的 IAM 管理的是員工與約聘人員：人數有限、相對固定，帳號由 IT 建立與控管。CIAM 管理的是客戶：人數多、難以預測，他們自己建立帳號，期待快速且有品牌感的登入流程，也需要能同意或撤回對自己資料的使用。

### 有開源的 CIAM 嗎？

有。Keycloak 和 Authgear 都以 Apache 2.0 授權開源，也都能自行部署。Keycloak 一開始是通用的身分與存取管理伺服器；Authgear 則是為面向客戶的應用程式打造，也可以由我們以私有雲方式替你維運。

### Keycloak 算是 CIAM 嗎？

Keycloak 自稱是開源的身分與存取管理（IAM）。它支援自助註冊、社群登入和自訂主題，所以很多團隊拿它來做客戶登入。不過，要做出精緻的客戶體驗，通常得自己開發自訂主題和擴充套件，並在每次升級時持續維護。

### 為了符合個資法，一定要導入 CIAM 嗎？

不一定。個資法並沒有要求使用 CIAM 產品，而是要求你在特定目的下合法蒐集、處理與利用個人資料，採取適當的安全維護措施，並回應當事人查詢、閱覽、更正、刪除等請求。CIAM 系統能讓這些工作更容易做到，因為同意紀錄、帳號資料與刪除流程都集中在同一個地方。
